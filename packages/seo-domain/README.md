# @ocentra/seo-domain

SEO audit domain for raw HTML, route metadata, robots, sitemap, JSON-LD, and internal-link validation.

## Ownership

This package owns reusable SEO audit logic only. App route metadata and server rendering stay in the main app:

- `src/seo/publicSeo.ts` resolves route titles, descriptions, canonicals, robots, sitemap entries, and JSON-LD inputs.
- `src/seo/seoServer.ts` injects route SEO into served HTML, renders raw fallback bodies, and creates `robots.txt` / `sitemap.xml`.
- `vite/plugins/seo-routes.ts` wires the SEO renderer into Vite dev and preview HTML routes.
- `functions/[[path]].ts` wires the same SEO renderer into Cloudflare Pages.
- `scripts/seo/generate-catalog-seo-data.mjs` generates `src/seo/generated/catalogSeoData.ts` from asset-editor catalog resources.
- `scripts/seo/audit-local.mjs` is the repo-local CLI wrapper around this package.

Do not rebuild ad-hoc SEO crawlers in app scripts. Add reusable checks here, then call them from the repo-local wrapper.

## Local Gate

Run from the repo root while the main app dev server is available:

```bash
npm run seo:audit
```

Useful options:

```bash
npm run seo:audit -- --base=http://127.0.0.1:3000 --max-pages=180 --max-depth=2 --catalog-sample=20
npm run seo:audit:full -- --base=http://127.0.0.1:3000
```

Run these for route/head SEO changes:

```bash
cmd /c npx vitest run src\seo\seoServer.test.ts src\seo\publicSeo.test.ts
cmd /c npx eslint --no-warn-ignored src\seo\seoServer.ts src\seo\seoServer.test.ts src\seo\publicSeo.test.ts
cmd /c npm run seo:audit -- --base=http://127.0.0.1:3000
cmd /c npm run seo:audit:full -- --base=http://127.0.0.1:3000
cmd /c npm run build
```

## What It Checks

- `robots.txt` exists and declares a sitemap.
- `sitemap.xml` is valid enough to expose `<loc>` URLs and can be crawled locally even when the sitemap uses production origins.
- Required route metadata exists: title, meta description, canonical, robots.
- Indexability matches route policy: public pages index, private/play/settings routes noindex.
- Raw HTML fallback exists for catalog, category, and game SEO pages.
- H1, text length, internal links, and JSON-LD are present where expected.
- JSON-LD parses as JSON.
- Duplicate titles, descriptions, and canonicals are rejected for indexable pages.
- Internal links are extracted and can be crawled up to the configured depth and page cap.
- Managed SEO fallback bodies are route-specific, so generic page fallback content cannot replace game, rules, catalog, or category fallback bodies after Vite HTML transforms.

## Phases

The local command audits:

1. Seed routes that must never regress.
2. Sitemap routes generated by the app.
3. Internal links discovered from audited raw HTML.
4. A bounded catalog sample from `packages/asset-editor/Resources/catalog/index.json`.

This is deliberately capped for local development. The current default audits the fixed seed routes, sitemap URLs, internal links, and 20 catalog samples with a 180-page cap. Use `npm run seo:audit:full` when you want the whole sitemap sweep across the generated catalog game and rules routes.

## Pass Criteria

Treat an SEO pass as incomplete until the served audit reports zero errors and zero warnings. A passing build or unit test is not enough by itself because the crawler verifies the actual raw HTML, route metadata, sitemap, robots, canonicals, fallback body content, JSON-LD, and internal links exposed by the running app.
